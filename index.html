AI didn't 10x you. Here's why.

The bottleneck moved.

You got a coding agent that writes a module in four minutes, and your week did not get five times better. That isn't a disappointing model. It's a bottleneck that moved, and nobody told you where it went.

It moved to you. The agent can run concurrently. You cannot. You have one attention and you spent it watching a machine work, so every agent you actively supervise runs at exactly the speed of one human — yours.

And nothing you learn stays learned. Task ten costs what task one cost, because nothing from tasks one through nine got written down anywhere the agent can reach. You didn't get a multiplier. You got a faster typist and a new way to be interrupted.

Two failures, two laws.

PACE is not a productivity system. It's two constraints on how you set work up — one for each failure.

Law One · fixes the attention problem

Act in Parallel

Your agents can run concurrently. You can't. So stop being the thing they wait on.

Structure work so it runs without you. Give a task enough context to go for an hour, get every blocking question answered in one message before it starts, and let it proceed on stated assumptions instead of stopping at the first fork.

A vague task interrupts you every four minutes. A well-specified task runs for an hour. That's the whole trade.

Metric: agent-hours per human-hour. If it's hovering near one, you're supervising, not dispatching.

Law Two · fixes the accumulation problem

Compound Effort

If your tenth task isn't faster than your first, you don't have a system. You have a habit.

Make every task leave something behind that makes the next one cheaper. Context written down, corrections folded back into the system, solved problems turned into things you can reuse.

The residue is the point. Fixing a wrong answer buys you one task. Fixing the context that produced it buys you every task after it.

Metric: is task ten cheaper than task one? If not, nothing you did in between was a system.

PACE — short 
## PACE
Act in Parallel: ask everything blocking up front in one message, then run
unattended on stated assumptions. Plan first, execute end to end, report once.
If blocked, park it and move to the next independent piece — never stall.

Compound Effort: read existing context and match it. When something's wrong
because context was missing, fix the context, not just the output. Extract
anything reusable. End with: what changed, what you assumed, what's open, and
what to add to the context files.

— PACE, wynter.ai/pace
